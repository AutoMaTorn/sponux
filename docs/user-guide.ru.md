## Установка

sponux нужны PyGObject и GTK 4 из вашего дистрибутива. Своих сторонних
зависимостей у него нет — всё остальное берётся из стандартной библиотеки
Python.

**Debian / Ubuntu.** Пакет объявляет зависимости сам, поэтому достаточно
одной команды:

```sh
sudo apt install ./sponux_0.2.3-1_all.deb
```

**Где угодно ещё** устанавливать нечего. Поставьте два системных пакета,
распакуйте sponux туда, где вы держите такие вещи, и запускайте оттуда:

```sh
sudo pacman -S python-gobject gtk4        # Arch; используйте свой пакетный менеджер
tar xf sponux-0.2.3.tar.gz -C ~/opt
~/opt/sponux-0.2.3/bin/sponux
```

Клонировать репозиторий вместо этого — то же самое, если вам удобнее следить за
проектом через git.

`bin/sponux` находит пакет рядом с собой, поэтому не нужны ни root, ни правка
`PATH`, ни процедура удаления — чтобы удалить, сотрите каталог. Привяжите
горячую клавишу к полному пути (`~/opt/sponux-0.2.3/bin/sponux`), и всё в этом
руководстве работает точно так же.

Архив несёт только то, что нужно для запуска, поэтому man-страницы в вашем
manpath не будет — читайте её на месте:
`man -l ~/opt/sponux-0.2.3/packaging/sponux.1`.

Это та же обёртка, которую `.deb` ставит как `/usr/bin/sponux`; разница только
в том, где она находит пакет.

Если GTK 4 у вас уже есть — а он есть, если установлено хоть одно приложение на
GTK 4, — sponux добавляет примерно 3 МБ Python-биндингов и 139 КБ самого себя.

Это руководство в пакет не входит: оно живёт в wiki проекта, поэтому его можно
исправить, не выпуская новую версию. Установленная копия несёт с собой
`man sponux`.

## Первый запуск

```sh
sponux
```

Окно появится в верхней части экрана. Набирайте текст для поиска, `Esc`
закрывает.

Первые три открытия строка подсказок под полем ввода говорит привязать клавишу
к `sponux` — ради этого программа и написана: запускать её из меню приложений
можно, но лаунчером так не пользуются. Дальше строка возвращается к префиксам
поиска. То же самое говорит `sponux --check` в разделе `startup`, пока установка
выглядит нетронутой.

Запустите `sponux` ещё раз — окно не откроется вторым экземпляром, а
переключится. В этом весь замысел: первый вызов поднимает небольшой резидентный
демон, а каждый следующий просто просит его показаться. Показ окна занимает
около 20 мс; первый вызов за сеанс — около 420 мс, потому что должны
загрузиться Python и GTK. [Запуск при входе в систему](#запуск-при-входе-в-систему)
убирает и это ожидание.

Заготовки конфигов с комментариями можно получить в любой момент:

```sh
sponux --write-config
```

Оба файла необязательны. Без них sponux работает на своих значениях по
умолчанию.

## Горячая клавиша

Привяжите сочетание к простой команде `sponux`. Больше ничего не нужно — ни
отдельного демона горячих клавиш, ни правил для оконного менеджера.

**i3 / sway:**

```
bindsym $mod+d exec --no-startup-id sponux
```

Перечитать конфиг — `$mod+Shift+r`. В отличие от rofi, sponux не требует
`--release` в привязке.

**GNOME, KDE, XFCE:** Параметры → Клавиатура → Свои комбинации, добавьте
запуск `sponux` и назначьте, например, `Super+Space`.

Окно намеренно не отдаётся оконному менеджеру (это X11 override-redirect — тот
же приём, что у rofi). Поэтому:

- тайловый менеджер не станет его тайлить, и правило `for_window` не нужно;
- окно никогда не становится *фокусным* для WM, так что i3 оставляет подсветку
  фокуса на том, с чем вы работали, — лаунчер лишь забирает ввод с клавиатуры,
  пока открыт;
- щелчок мимо окна или переключение на другое окно закрывает его.

Окно появляется на том мониторе, где находится курсор.

## Запуск при входе в систему

Лаунчер открывается быстро именно *потому, что демон уже запущен*. Поднимите
его при входе в систему — и даже первое нажатие будет мгновенным:

```sh
sponux --autostart on      # «off» — отключить, без аргумента — показать состояние
```

Команда создаёт `~/.config/autostart/sponux.desktop`, который запускает
`sponux --daemon`: резидентно и без окна. На экране ничего не появится, пока вы
не нажмёте горячую клавишу.

**Простые оконные менеджеры не читают `~/.config/autostart`.** Под i3, sway и
подобными строку нужно добавить в конфиг самого менеджера — `--autostart on`
предупредит об этом, когда обнаружит такой случай:

```
exec_always --no-startup-id sponux --daemon
```

Именно `exec_always`, а не `exec`: i3 выполняет `exec` только при первом
старте, поэтому с `exec` демон не вернётся ни после `Ctrl+Q`, ни после
перезапуска i3. Запустить команду дважды ничего не стоит — `--daemon` проверяет,
не занято ли имя на сессионной шине, и молча выходит, если демон уже работает.

## Как пользоваться

| Клавиша | Действие |
| --- | --- |
| набор текста | поиск приложений, файлов и вычисления |
| ↑ / ↓ | перемещение по списку |
| `Enter` | запустить, открыть или скопировать результат вычисления |
| `Ctrl+Enter` | открыть папку, содержащую выбранный файл |
| `Ctrl+C` | скопировать путь к выбранному файлу |
| `Shift+Enter` | открыть с помощью… (и при желании запомнить выбор) |
| `Shift+Delete` | забыть то, что ранжирование узнало о выделенном |
| `Esc` | скрыть окно |
| `Ctrl+Q` | завершить демон |

Клавиши, применимые к выбранному результату, показаны под списком, так что
запоминать ничего не нужно.

Скопированный текст передаётся менеджеру буфера обмена, так что он переживает
демон — если менеджер буфера запущен. Без него (большинство минимальных
конфигураций с оконным менеджером) буфер по-прежнему умирает вместе с
процессом, как у любого X11-приложения.

**Калькулятор** понимает обычные выражения — `2+2*10`, `sqrt(2)`, `sin(pi/2)`,
`1/7`, — а `Enter` копирует результат. Это ограниченный вычислитель выражений,
а не `eval()`: вызвать что-либо кроме известных ему математических функций он
не может.

### Как сузить поиск

Префикс ограничивает результаты одним видом, а ведущий `/` или `~/` означает,
что вы набираете путь, а не поисковый запрос:

| Набрать | Получите |
| --- | --- |
| `f:` `file:` | только файлы |
| `a:` `app:` | только приложения |
| `c:` `=` | только калькулятор — `=1/7` |
| `/…` `~/…` | этот путь и дополнения его последнего компонента |

Всё это перечислено под строкой поиска, пока она пуста, и исчезает, едва вы
начинаете набирать.

### Ввод пути

Это способ выйти *за пределы* индекса файлов, и о нём стоит знать: индекс
намеренно не покрывает всю файловую систему.

- `/etc/ho` → `/etc/hosts`. Индекс не участвует; `/etc` вообще не
  индексируется.
- `~/pro` → `~/projects`.
- Слеш в конце показывает содержимое каталога: `~/Documents/`.
- Скрытые записи появляются, как только вы наберёте точку, — как в шелле.
- Дополняется только последний компонент и только по началу имени: как в
  шелле, а не нечётким поиском, как выше.
- Набранный путь всегда стоит выше любого результата поиска. Вы назвали его
  точно, угадывать больше нечего.

Считаются только `/` и `~/`. Относительные пути вида `./x` — нет, потому что
им не от чего отсчитываться: демон работает с момента входа в систему.

## Чем открывать файлы

Нажмите `Shift+Enter` на файле — получите список приложений: сначала те,
которыми вы уже что-то открывали, затем зарегистрированные для этого типа,
затем все остальные установленные. Набирайте текст для фильтрации, `Enter` —
открыть, `Esc` — вернуться к поиску.

Первая строка этого списка — переключатель. Включите его, и выбор *заодно*
запишется в `config.toml` как правило, так что следующий файл того же вида
откроется так же без вопросов. В каждой строке видно, что именно будет
сохранено, ещё до нажатия Enter. При выключенном переключателе не пишется
ничего.

Правила можно писать и руками, в `~/.config/sponux/config.toml`:

```toml
[open]
directory = "thunar"        # каталоги
file = "kitty -e nvim"      # любой файл, для которого нет более точного правила
default = "xdg-open"        # последнее средство

[open.name]                 # по имени файла; допустимы "*" и "?"
".*rc" = "code"
"Makefile" = "code"

[open.extension]            # по расширению, без точки
py = "code --goto {path}:1"
png = "eog"

[open.mime]                 # по mime-типу; допустима "*"
"text/*" = "code"
"video/*" = "mpv"
```

Правила проверяются от более точных к более общим — `name`, `extension`,
`mime`, затем `directory` / `file`, затем `default`, — и побеждает первое
совпадение. То, что не совпало ни с чем, откроется приложением по умолчанию из
вашего окружения.

Три вещи, которые сэкономят время:

- **`[open.name]` — единственное правило, достающее до файла без расширения**,
  а это как раз те файлы, которые вам важны: `.bashrc`, `Makefile`,
  `~/.config/i3/config`.
- **`file` перехватывает всё**, включая видео и архивы. Обычно людям нужно
  другое: оставить его незаданным и перечислить расширения.
- **Не всякий код — это `text/*`.** JSON — `application/json`, скрипт
  оболочки — `application/x-shellscript`, а файл `.ts` определяется как
  *Qt Linguist*. Такие лучше задавать расширением, а не надеяться на
  mime-шаблон. Если сомневаетесь — спросите: `sponux --which somefile.ts`.

Путь к файлу добавляется к команде в конец, если только вы не напишете
`{path}` сами и не поставите его туда, куда нужно. Ведущая `~` в команде
раскрывается. Если команду не удалось запустить, sponux откроет файл
приложением по умолчанию, а не сделает вид, что ничего не произошло, и напишет
причину в stderr.

## Что находит поиск файлов

Поиск файлов опирается на небольшой индекс *имён файлов* (не содержимого) в
вашем домашнем каталоге; индекс поддерживается в актуальном состоянии по мере
появления и исчезновения файлов. Что в него попадает — решаете вы:

```toml
[index]
roots = ["~", "/etc"]        # где вообще искать
include = ["~/.config"]      # скрытые деревья, которые всё же индексировать
exclude = ["~/.config/BraveSoftware/*", "*.iso"]
skip = ["Steam"]             # имена каталогов, отсекаемые где угодно
unskip = ["build"]           # …или убранные из встроенного списка отсечений
hidden = false               # индексировать все точечные файлы (обычно это чересчур)
follow_symlinks = true       # ходить по символическим ссылкам на каталоги
watch = true                 # поддерживать индекс актуальным при изменениях
interval = 900               # секунды между полными перестроениями; 0 — отключить
max_files = 200000
max_watches = 8192
```

По умолчанию индексируется домашний каталог, а скрытые файлы и каталоги
пропускаются вместе со мусором сборок и кэшей (`.git`, `node_modules`,
`__pycache__`, `.cache`, `.venv`, `target`, `build`, `dist`, …).

Это же значение по умолчанию скрывает и ваши конфиги — для них и существует
`include`. Он перечисляет скрытые деревья, которые нужно индексировать
несмотря на правило, причём каталоги по пути к ним обходятся *без* индексации:
`include = ["~/.local/share/applications"]` проходит через `~/.local` и
`~/.local/share`, не втягивая всё прочее, что там лежит.

`exclude` сильнее всего остального. Его шаблоны — glob-маски по всему пути,
причём `*` пересекает разделители каталогов, поэтому `~/Videos/*` покрывает
дерево целиком.

**`include` предпочтительнее `hidden = true`.** На одном довольно обычном
домашнем каталоге: 618 записей с настройками по умолчанию, 672 — с
подключённым `~/.config` и исключёнными профилями браузеров внутри него, 7821 —
вместе с этими профилями и 91743 — с `hidden = true`, после чего в результатах
находится в основном состояние приложений, а не ваши файлы.

По символическим ссылкам на каталоги sponux ходит по умолчанию. Отключается
через `follow_symlinks = false` — но если вы держите dotfiles одним
репозиторием, слинкованным на место, то именно этот обход и делает
`~/.config/nvim/init.lua` находимым вообще. Циклы из ссылок обрабатываются
безопасно.

Перестраивать индекс вручную не нужно: демон следит за каждым
проиндексированным каталогом, поэтому созданный файл находится примерно через
десятую долю секунды, а удалённый перестаёт предлагаться. Полное перестроение
выполняется при старте и каждые 15 минут — как страховка, потому что под
нагрузкой ядро может потерять уведомления об изменениях, и иначе этого никто
не заметит. Если нужно сейчас:

```sh
sponux --reindex
```

## Ранжирование: нужное — выше

sponux запоминает, что и когда вы открывали, и приподнимает такие результаты.

```toml
[rank]
frecency = true      # то, что вы открываете, выше того, что просто совпало
weight = 25          # максимум, который результат может получить за свою историю
indirect = 0.5       # сколько стоит приложение, открывшее файл по правилу
```

Два файла с именем `config` больше не равны — первым идёт тот, который вы
правили сегодня утром. Свежесть весит больше количества: два раза сегодня
лучше, чем десять раз в прошлом году. Счётчик сжимается логарифмически, поэтому
то, что вы однажды открывали в цикле, не будет доминировать во всех
последующих поисках.

Прибавка намеренно ограничена величиной меньше разрыва между качествами
совпадения: история решает почти-ничьи, но никогда не перебивает запрос —
совпадение по началу имени всё равно обойдёт часто используемое совпадение по
подстроке.

Приложения считаются так же — и не только когда вы запускаете их по имени.
Открыть что-то *с помощью* приложения — тоже его использование: и через
`Shift+Enter`, и по правилу `[open]`. Поэтому редактор, которым вы открываете
каждую папку проекта, поднимается в поиске приложений и в следующий раз стоит
первым в списке `Shift+Enter`, а не там, куда его поместила система. Порядок
приложений, которые вы ни разу не выбирали, остаётся прежним.

Считается не всё одинаково. Набрать имя приложения или выбрать его в списке
`Shift+Enter` — это вы говорите, какое приложение нужно; сработавшее правило
`[open]` говорит лишь то, что файл открыли: приложение в правиле выбрали один
раз, и каждый следующий файл просто повторяет то давнее решение. Поэтому
приложение, засчитанное по правилу или как системный дефолт, стоит половину
использования, и два автоматических открытия весят ровно столько же, сколько
один осознанный запуск. `indirect = 1` — считать одинаково, `indirect = 0` —
не считать такие открытия вовсе.

`sponux --which ПУТЬ` покажет, что заработал файл, каким приложением он
откроется и что заработало это приложение.

### Забыть

Файл, однажды открытый не тем приложением, папка, в которую зашли по ошибке,
давно удалённый проект — лаунчер продолжает их предлагать. `Shift+Delete` на
выделенном результате забывает его: история уходит, сам результат остаётся, а
список пересортировывается на месте. Клавиша предлагается только там, где есть
что забывать.

Из терминала — по шаблону:

```sh
sponux --forget notes        # всё, в чьём пути или id приложения есть "notes"
sponux --forget '*.py'       # шаблон с подстановкой берётся как написан
sponux --forget --all        # начать с чистого листа
```

Каждое удаление печатается, потому что отменить его нельзя. Больше ничего не
трогается: забыть файл — не то же самое, что убрать правило, которым он
открывается, а забыть приложение — не удалить его.

`frecency = false` — ранжировать только по запросу.

## Окно и клавиши

Всё здесь необязательно и живёт в `config.toml`. Всё применяется при следующем
открытии лаунчера — перезапускать демон не нужно.

```toml
[window]
width = 640              # ширина карточки в пикселях
max_results = 9          # сколько строк показывает список
position = "top"         # или "center"
top_fraction = 0.22      # насколько ниже верха монитора стоит "top"
hide_on_focus_loss = true
debounce = 60            # мс без ввода, после которых запускается поиск
```

`position = "top"` — это размещение как у Spotlight: карточка стоит на
`top_fraction` высоты монитора, чуть выше середины. Так читается лучше, чем
ровно по центру, и остаётся место, чтобы список результатов рос вниз, а сама
карточка не двигалась. `position = "center"` центрирует её по вертикали.

`hide_on_focus_loss = false` оставляет лаунчер открытым при щелчке мимо, так
что закрыть его можно только Escape или горячей клавишей.

### Клавиши

```toml
[keys]
reveal = "<Ctrl>Return"      # открыть папку, содержащую выбранный файл
copy_path = "<Ctrl>c"        # скопировать путь к выбранному файлу
open_with = "<Shift>Return"  # выбрать приложение для этого файла
forget = "<Shift>Delete"     # забыть, что ранжирование узнало об этом
close = "Escape"             # скрыть окно
quit = "<Ctrl>q"             # завершить демон
```

Синтаксис акселераторов GTK, тот же, что у `bindsym` в i3: `"<Ctrl>Return"`,
`"<Shift><Alt>c"`, `"F2"`. `sponux --check` печатает, что в итоге привязано к
каждому действию, и сообщает обо всём, что не смог разобрать: непонятная
привязка игнорируется с сохранением значения по умолчанию, а не молча перестаёт
работать.

Три вещи закреплены намеренно:

- **Набор текста, стрелки и Enter.** Именно они делают это лаунчером, а не
  раскладкой клавиш, и переназначение — способ запереть себя снаружи.
- **Escape всегда закрывает окно**, что бы ни было написано в `close`. Опечатка
  в `config.toml` не может оставить вас без выхода.
- **`unmanaged`** — приём с X11 override-redirect, описанный в разделе
  [Горячая клавиша](#горячая-клавиша), — сюда не вынесен. Он применяется один
  раз, при создании окна, поэтому в отличие от всего остального не мог бы
  подействовать без перезапуска; он остался в `sponux/config.py` на редкий
  случай оконного менеджера, которому его нужно отключить.

Строка подсказок под результатами строится по действующим привязкам, так что
после переназначения она говорит правду, а не значения по умолчанию.

Привязка сопоставляется с **физической клавишей**, а не только с символом,
который выдала клавиатура. Поэтому `"<Ctrl>c"` продолжает работать при активной
кириллической, греческой или любой другой нелатинской раскладке — где эта
клавиша иначе отдала бы кириллическую «с» и не совпала бы ни с чем.

## Внешний вид

Внешний вид целиком описывается в `~/.config/sponux/style.css`. Встроенная
таблица стилей тёмная и управляет всем окном из горстки переменных, поэтому
перекрасить его — значит переопределить несколько из них, а не копировать весь
файл:

```css
:root {
    --sponux-font: "JetBrainsMono Nerd Font";
    --sponux-font-size: 16px;
    --sponux-bg: #1e1e2e;
    --sponux-accent: #f38ba8;
    --sponux-radius: 10px;
}
```

| Переменная | |
| --- | --- |
| `--sponux-font` | имя гарнитуры; если не задано — шрифт интерфейса вашего окружения |
| `--sponux-font-size` | размер заголовка результата: запрос, пути, метки и подсказки выводятся из него, поэтому одно это число масштабирует всё окно |
| `--sponux-bg` `--sponux-fg` | фон; заголовки и текст запроса |
| `--sponux-muted` `--sponux-dim` | пути и описания; метки, подсказки, placeholder |
| `--sponux-accent` | выделение и текстовый курсор |
| `--sponux-line` `--sponux-border` `--sponux-shadow` | разделитель и заливка метки, рамка, тень |
| `--sponux-radius` `--sponux-row-radius` | скругление окна и строк результатов |

Ваш файл загружается *после* встроенного, поэтому всё, что вы задали,
побеждает.

Имя гарнитуры указывайте точно так, как её знает fontconfig, и проверяйте имя,
прежде чем ему доверять: при ошибке fontconfig молча подставит что-то другое, и
это выглядит так, будто настройка не работает.

```sh
fc-match "JetBrainsMono Nerd Font"
```

Всё, до чего переменные не достают, — обычный CSS для GTK. Селекторы:
`.sponux-card`, `.sponux-search`, `.sponux-sep`, `.sponux-results`,
`.sponux-row`, `.sponux-title`, `.sponux-subtitle`, `.sponux-badge` и
`.sponux-hints`.

Правки в любом из двух конфигов применяются при следующем открытии лаунчера.
Перезапускать демон не нужно.

## Конфиги в dotfiles-репозитории

Оба файла — обычный текст без машинно-управляемых секций, так что им вполне
место в dotfiles-репозитории. Слинкуйте их — по файлу или каталогом целиком:

```sh
ln -s ~/dotfiles/.config/sponux ~/.config/sponux
```

sponux аккуратен с такой схемой:

- когда он сам записывает правило (переключатель «запомнить»), он **пишет
  сквозь символическую ссылку**, поэтому правка попадает в ваш репозиторий, а
  ссылка остаётся ссылкой;
- резервные копии, которые он делает перед перезаписью, кладутся в
  `~/.local/state/sponux/`, а не рядом с оригиналом — никаких случайных
  `.bak`-файлов в вашем репозитории;
- индекс ходит по символическим ссылкам на каталоги, поэтому конфиги, лежащие
  в репозитории и слинкованные в `~/.config`, находятся по тому пути, которым
  вы ими и пользуетесь.

## Если что-то не так

На большинство вопросов отвечают две команды:

```sh
sponux --check                       # всё, что не так в config.toml
sponux --which ~/.config/i3/config   # чем и почему откроется этот файл
man sponux                           # полный справочник
```

`--check` проходит по всем правилам, проверяет, что каждая команда есть в
`PATH`, и заодно корни и include-пути индекса. `--which` печатает тип
содержимого файла, сработавшее правило, точную команду, которая будет
выполнена, и сообщает, если программы нет.

**Куда деваются ошибки.** Запущенный по горячей клавише или при входе в
систему, sponux не имеет терминала, куда печатать, поэтому всё, о чём он
сообщает во время работы, дописывается ещё и в
`~/.local/state/sponux/sponux.log`, а хвост этого файла — последнее, что
печатает `sponux --check`. Туда и надо смотреть, когда что-то один раз не
получилось и не оставило следа на экране. Файл ограничен — на 64 КиБ он
ротируется в `sponux.log.1`, а сообщение, повторяющееся в пределах минуты,
считается, а не пишется заново, — и оба файла можно удалять в любой момент.

Для той горстки сбоев, когда вы нажали клавишу и ничего не произошло —
настроенная программа не запустилась, `config.toml` игнорируется целиком, —
sponux ещё и показывает уведомление на рабочем столе, если ваш сеанс их
показывает. Фоновые неприятности вроде стиля, сохранённого на середине правки,
или неудачного обновления индекса, идут только в журнал.

**Горячая клавиша не срабатывает.** Запустите `sponux` в терминале и прочитайте
ошибку. Учтите: окно намеренно невидимо для инструментов оконного менеджера —
в `wmctrl -l` и `_NET_CLIENT_LIST` его не будет. Убедиться, что оно
существует:

```sh
xwininfo -root -tree | grep '"sponux"'
```

**Похоже, работает старая версия.** Возможно, у вас две установки: пакетная в
`PATH` и рабочая копия исходников. Они делят одно имя на сессионной шине, так
что на все нажатия отвечает тот демон, который поднялся первым. `sponux
--check` скажет, какой именно: его pid, каталог, откуда он импортирует пакет, и
версию этой копии, — и предупредит, если это не то дерево, из которого вы
спрашиваете. Откройте лаунчер, нажмите `Ctrl+Q`, чтобы остановить этот демон, и
запустите нужный:

```sh
sponux --daemon          # или /путь/к/исходникам/bin/sponux --daemon
```

`Ctrl+Q` — надёжный способ его остановить. Не используйте
`pkill -f 'm sponux'`: этот шаблон совпадает и с оболочкой, в которой вы его
набираете, так что вместе с демоном можно убить собственный сеанс.

**Файл точно есть, но не находится.** Значит он вне индекса, а не потерян.
Либо добавьте его дерево в `[index] include`, либо просто наберите путь — для
этого индекс вообще не нужен. `sponux --check` покажет, какие корни и include
действуют сейчас.

**Открылось не тем приложением.** `sponux --which ФАЙЛ` назовёт сработавшее
правило. Обычная причина — mime-шаблон, который не подходит; см. замечание про
`text/*` выше.

**Настройка шрифта игнорируется.** Почти наверняка имя гарнитуры не такое, как
его называет fontconfig; проверьте через `fc-match`. «JetBrains Mono» и
«JetBrainsMono Nerd Font» — разные имена, и разрешается только установленное.

**Мой style.css как будто не читается.** Ошибка разбора CSS выводится с
указанием файла и номера строки — в конце `sponux --check`, а если демон
запущен из терминала, то и в stderr.

**Правки config.toml ни на что не влияют.** Если файл не разбирается как TOML,
он игнорируется целиком, а не применяется наполовину. `sponux --check` скажет
об этом и укажет позицию синтаксической ошибки.

**Первое нажатие за сеанс медленное.** Это запускается демон. См.
[Запуск при входе в систему](#запуск-при-входе-в-систему).

**Под Wayland** окно не может разместить себя через X11. С установленным
опциональным gtk4-layer-shell (`gir1.2-gtk4layershell-1.0` в Debian) sponux
становится overlay-слоем: композитор сам его плавает, центрирует и даёт фокус
по протоколу. Без библиотеки позиционирование остаётся за композитором.
Всё остальное работает.

## Что sponux пишет на диск

| Путь | |
| --- | --- |
| `~/.config/sponux/` | ваши два конфига — записываются только `--write-config` или переключателем «запомнить» |
| `~/.cache/sponux/index.db` | индекс имён файлов; можно удалять, он перестроится |
| `~/.local/state/sponux/usage.db` | что вы открывали, для ранжирования |
| `~/.local/state/sponux/sponux.log` | что пошло не так во время работы; ротируется на 64 КиБ, можно удалять |
| `~/.local/state/sponux/first-run` | сколько раз открывалось окно, до четырёх — только чтобы подсказка перестала показываться |
| `~/.local/state/sponux/*.bak` | предыдущая версия конфига, который sponux заменил |
| `~/.config/autostart/sponux.desktop` | только если вы попросили `--autostart on` |

## Удаление

```sh
sudo apt remove sponux           # если ставили .deb
rm -rf ~/opt/sponux-0.2.3        # если распаковывали архив
```

Ни то, ни другое не трогает ваши конфиги, индекс и историю. Чтобы убрать и их:

```sh
sponux --autostart off
rm -rf ~/.config/sponux ~/.cache/sponux ~/.local/state/sponux
```

Не забудьте убрать горячую клавишу из конфига оконного менеджера.

## Сборка из исходников

Чтобы пользоваться sponux, собирать ничего не нужно — клон работает как есть,
через `./bin/sponux`. Собирайте только если вам нужен один из устанавливаемых
артефактов.

Ничего из этого не требует pip, setuptools, виртуального окружения или доступа в
сеть. Сборщики — обычный Python на стандартной библиотеке.

**Что понадобится:**

- Python 3.11 или новее.
- Только для `.deb`: `dpkg-deb`. Он входит в пакет `dpkg`, который в Debian и
  Ubuntu помечен как Essential — то есть уже стоит, — а в Arch и Fedora
  доступен как `dpkg`.
- Необязательно: `lintian`. `mkdeb.py` прогоняет его по готовому пакету, если он
  установлен, и пропускает, если нет.

**Сборка:**

```sh
git clone https://github.com/AutoMaTorn/sponux && cd sponux

python3 tools/mkdeb.py         # dist/sponux_0.2.3-1_all.deb
python3 tools/mktarball.py     # dist/sponux-0.2.3.tar.gz
python3 tools/mkwheel.py       # dist/sponux-0.2.3-py3-none-any.whl
```

| Что именно | Для чего |
| --- | --- |
| `.deb` | Debian и Ubuntu: `sponux` в `PATH`, пункт в меню, `man sponux` |
| `.tar.gz` | где угодно ещё: распаковать и запускать, без шага установки |
| wheel | только если вам целенаправленно нужен `pip` — и сначала прочитайте предупреждение в разделе [Установка](#установка) |

**Прогон проверок:**

```sh
for t in tests/test_*.py; do python3 "$t" || break; done
```

Каждая запускается сама по себе и печатает по строке на проверку. Весь набор
занимает около двух секунд, половина из них — `test_index.py`: он строит
настоящее дерево каталогов в `/tmp` и ждёт живых событий файловой системы.

**Оба архива воспроизводимы.** Все метки времени в них берутся из
`packaging/changelog`, а не с часов, записи отсортированы, владелец везде root —
поэтому две сборки одного дерева дают побайтово одинаковые файлы. Значит, можно
сверить артефакт, который вам кто-то передал, с тем, что вы собрали сами:

```sh
sha256sum dist/sponux-0.2.3.tar.gz
```

**Смена версии** — это правка трёх файлов: `pyproject.toml`,
`packaging/changelog` и `sponux/__init__.py`. Сборщики сверяют их между собой и
отказываются работать при расхождении, так что выпустить наполовину поднятую
версию не получится, — но заполнить остальные два за вас они не могут. Строка
`.TH` в `packaging/sponux.1` тоже называет версию, и её никто не проверяет.
